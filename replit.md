# Overview

Neo FMC is a multi-tenant microfinance SaaS platform designed for the Egyptian market. It aims to provide a comprehensive solution for microfinance operations, including loan origination, management, financial tracking, and regulatory reporting. The project emphasizes robust security through database-enforced Row-Level Security (RLS) for physical tenant isolation, ensuring data privacy and compliance. Its core capabilities span client management, loan product configuration, dynamic loan workflows, integrated e-payments, and advanced reporting. The platform is built to be highly scalable, secure, and user-friendly, supporting both Arabic (RTL) and English (LTR) interfaces.

## System Architecture

The project is structured as a pnpm monorepo using TypeScript, featuring a React + Vite frontend and an Express 5 backend. PostgreSQL is used for the database, leveraging Drizzle ORM.

**Key Architectural Decisions:**

*   **Monorepo Structure:** Uses pnpm workspaces to manage `api-server` (Express backend) and `neo-fmc` (React + Vite frontend) artifacts, alongside shared `lib` packages for API specifications, client code generation, and database schema.
*   **Multi-tenancy:** Implemented at the row level with a `tenant_id` UUID column in every tenant-scoped table. Authentication context automatically filters data by `tenant_id`. SuperAdmin users have `tenantId = null` and bypass tenant-specific restrictions.
*   **Row-Level Security (RLS):** PostgreSQL's native RLS is extensively used across all tenant-scoped tables. An `neo_fmc_app` database role enforces RLS, preventing cross-tenant data access even if application-level filtering fails. A `tenantRlsMiddleware` dynamically sets the `app.current_tenant_id` for each request, ensuring transaction-scoped tenant isolation. A transparent `db` proxy uses `AsyncLocalStorage` to manage transaction-scoped database connections without requiring changes in route handlers.
*   **Authentication:** Supports both Email/Password (JWT-based) and Replit Auth (OIDC/SSO). JWTs are stored in `localStorage`, and Replit Auth uses cookie-based sessions. `requireAuth` middleware handles both.
*   **UI/UX:** The frontend is a React + Vite application using TailwindCSS for styling, Lucide icons, and Recharts for data visualization. It supports RTL Arabic as the primary language and LTR English, with a toggle for language switching and preference persistence. Three theme modes available: **Dark** (deep navy financial), **Light** (clean professional business), and **Cheerful** (warm rose/coral tones). Theme selection is persisted to localStorage and accessible via a dropdown in the header. All themes use CSS custom properties for seamless switching. **Mobile-first responsive design:** Header compact on mobile (h-14), page title always visible with truncation, content padding scales (p-3→p-8). All dialogs/modals use bottom-sheet pattern on mobile (slide up from bottom, rounded top corners, 95vh max height) and centered on desktop. Tab bars are horizontally scrollable with `overflow-x-auto` and `whitespace-nowrap`. Toggle switches have 48x28px touch-friendly targets with ARIA attributes. Data tables hide non-essential columns on smaller viewports. Grid layouts use responsive breakpoints (e.g., `grid-cols-2 sm:grid-cols-4`).
*   **API Design:** A RESTful API is implemented using Express, with OpenAPI specifications for documentation and `Orval` for client code generation (React Query hooks, Zod schemas).
*   **Data Validation:** Zod is used for robust schema validation, integrated with `drizzle-zod`.
*   **Database Schema:** A comprehensive schema including core microfinance entities like `tenants`, `users`, `clients`, `fund_products`, `loan_requests`, `loans`, `payments`, `installments`, and financial ledgers (`gl_accounts`, `journal_entries`). Extended tables support advanced features such as `expenses`, `revenues`, `epayment_configs`, `custom_workflows`, `credit_limits`, `guarantees`, `cheques`, and `notifications`.
*   **Credit Limit Auto-Consumption:** When a loan is disbursed, the system automatically checks if the client has an active credit limit and deducts the loan amount from the available balance. Journal entry recorded for audit trail.
*   **Client Document Attachments:** Clients support multiple PDF attachments (National ID, Proof of Address, Income Proof, Guarantees, Contracts). Documents stored with filename, type, upload timestamp (date + time AM/PM), version number. Upload via `/api/documents/upload`, list via `/api/documents?clientId=` or `?guaranteeId=`, download via `/api/documents/download/:id`. Document versioning: uploading a new doc of same type increments version, old versions are kept.
    *   **Client Profile Panel:** Clicking a client name from Loans, Loan Requests, Collection, Cheques, or Guarantees pages navigates to `/clients?clientId=xxx` and auto-opens a comprehensive client profile modal. Profile shows: basic info (name, code, national ID, phone), addresses (primary/secondary), KYC status with badge, identification documents (job title, profession license, tax ID, commercial registration, issuance/expiry dates), attached documents list with download links, and action buttons (Edit Profile, Update KYC, Manage Attachments, Risk Check). The client name in the Clients table is also clickable to open the profile. API endpoints (`/api/installments/overdue`, `/api/installments/upcoming`, `/api/installments/my-tasks`) all return `clientId` alongside `clientName` to enable deep linking.
*   **Role-Based Dashboards:** `Dashboard.tsx` is a role-aware router that renders a dedicated dashboard component for each of the 10 user roles. Each dashboard is a separate component under `src/pages/dashboards/`. Roles → dashboards: `TenantAdmin/SuperAdmin` → TenantAdminDashboard (full portfolio + officer performance + financial ratios + collection trends + pending approvals alert); `BranchManager` → BranchManagerDashboard (branch-scoped KPIs + PAR + officer performance); `LoanOfficer` → LoanOfficerDashboard (personal performance, my active requests, quick actions); `CollectionOfficer` → CollectionOfficerDashboard (overdue installments, collection tasks, daily payments); `Cashier` → CashierDashboard (today's receipts, daily closing status, recent payments); `DataEntry` → DataEntryDashboard (recently added clients, pending requests, quick add links); `Auditor` → AuditorDashboard (audit log, compliance flags, PAR chart, financial ratios); `Accountant` → AccountantDashboard (unposted journals, expenses, monthly closing, GL links); `FinancialController` → FinancialControllerDashboard (OSS, yield, PAR, pending approvals, collection trend); `CFO` → CFODashboard (strategic overview, all financial ratios, 12-month area trend, PAR breakdown). Shared UI utilities in `src/pages/dashboards/shared.tsx`.
